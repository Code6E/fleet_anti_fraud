# 本地 S3 数据库（离线调试用）

从内网 S3（`http://88.88.1.63:8080`，桶 `004zhlhccbx`）拉取的代表性查询文件镜像，
用于**脱离公司内网环境调试** s3-file-manager 项目。共 80 个文件，全部为真实业务文件。
> 2026-11 补充：新增 **45 个具有代表性的「10 月前」船舶过往投保情况 result 文件**（见下方「补充清单」）。

## 目录结构（镜像 S3 原始布局）

```
本地S3数据库/
├── upload/      14 个上传文件（船舶 + 企业）        ← 对应 S3 的 upload/ 目录
├── download/    60 个结果文件（含补充的 45 个 10月前船舶结果） ← 对应 S3 的 download/ 目录
├── root/         6 个根目录散落文件（含 1 个子文件夹） ← 对应 S3 根目录的脏数据
├── manifest.json 拉取清单（S3 key、字节数、文件魔数、备注）
└── README.md     本说明
```

## 两种文件格式

### 船舶格式（2026 年，当前项目主场景）
- **上传文件**（6 列）：`序号 | 查询服务编号 | 船舶识别号 | IMO号 | 船舶中文名称 | 船舶英文名称`
  标识四项填一项即可，sheet 名通常为 `A01入参`
- **结果文件**（17 列）：上述 6 列 + `险种小类 | 当年及过去3年满期赔付率（已决）|（已决+未决）| 近3年出险原因及数量 | 近3年赔案金额 | 近3年赔案区间及案件数量 | 近1年起保当月/2个月/3个月出险保单数量及占比 | 近3年保单涉及保险公司数量 | 最近保单涉及保险公司代码 | 近3年单均保额保费`
  一条船按险种小类拆成多行返回
- 命名规范：`船舶_000012_YYYYMMDD_分公司名.xlsx`，结果同名加 `_result`

### 企业格式（2024-2025 年，旧测试数据）
- **上传文件**（4 列）：`序号 | 查询类别 | 名称 | 证件号码`
- **结果文件**（18 列）：上述 4 列 + `险种 | 过去3年各年满期赔付率（已决/已决+未决）| 近1年保费金额 | 单均保额保费 | 起保当日/2日内/3日内出险保单数量及占比 | 近1年出险原因及数量 | 近1年保单最大保额 | 最大保额保单的保险期限/货物名称/起运地/目的地`
- 命名规范：`A01_000012_YYYYMMDD-分公司名.xlsx`（连字符有无不统一，属真实脏数据）

## 典型边界样例（真实脏数据，用于健壮性测试）

- **大小写**：`_RESULT.xlsx`（内蒙古、大连）
- **空格**：`湖北分公司_result .xlsx`、`上海分公司 _result.xlsx`、`上海分公司 (11).xlsx`
- **双后缀**：`船舶_000012_20260609_辽宁分公司.xlsx_result.xlsx`
- **.xls 扩展名**：`root/A01_000012_20250306-安徽分公司.xls`
- **上传文件错放 download/**：`船舶_000012_20260624_广东分公司.xlsx`
- **完全不规范命名**：`新疆分公司0725 - 副本.xlsx`、`广东汕头2.24.xlsx`、`12.10-A01_000012_20241210-山东分公司_result.xlsx`
- **自建子文件夹**：`root/9.30黑龙江运力通供应链管理有限公司/`
- **非规范序号**：`船舶_000012_20260525_1安徽分公司.xlsx`、`船舶_000012_202605281安徽分公司.xlsx`
- **大文件**：`A01_000012_20250516-山东分公司_result.xlsx`（122KB，1325 行）
- **不同服务编号**：`A01_000001_*`（甘肃、湖南）vs `A01_000012_*`

## 如何刷新（需在内网环境下）

```bash
cd s3-file-manager/server
node fetch_s3_samples.mjs           # 重新拉取主清单（88 个文件 = 原 43 + 补充 45）
```

脚本只读下载，不上传、不删除任何 S3 对象。文件清单维护在
`s3-file-manager/server/fetch_s3_samples.mjs` 的 `SAMPLES` 数组中，可自行增删。

> ⚠️ 全部为真实业务数据（含船舶/企业名称与承保理赔信息），仅限本地调试使用，请勿外传。
