# 船舶险智盾解读报告生成器

把船舶险智盾查询数据转成总公司标准格式的 Word 核保解读报告。核心价值是**把机械的字段解读、指标推算、评级套用和排版工作自动化**，让人只做专业判断。

## 前置条件

- Python 3，需 `openpyxl`、`lxml`（缺则 `pip install openpyxl lxml`）
- 数据表须含「船舶中文名」「险种小类」两列以定位表头；其余列按名匹配，顺序可变

## 快速开始

单船：

```bash
python scripts/build_report.py \
  --source "<数据表.xlsx>" --ship 万国顺达 \
  --out-dir "<输出目录>" --insurers "<机构代码表.xlsx>" \
  --extras "<补充档案.json>" --current-year 2026
```

批量（数据表中全部船舶，每船一份报告 + `_batch-summary.json`）：

```bash
python scripts/build_report.py \
  --source "<数据表.xlsx>" --all \
  --out-dir "<输出目录>" --insurers "<机构代码表.xlsx>" \
  --extras "<补充档案.json>" --current-year 2026
```

`--extras` 是 JSON：`{"船名": {"ship_id": "CN20104302285", "gt": 17167, "ship_type": "散货船"}}`。
数据表里通常**没有**总吨位、船舶类型、有时也没有识别号，必须靠这个文件补——见「数据缺口」一节。

## 执行流程

1. **先读参考资料**：`references/字段解读规则.md` 讲清了每个字段的口径和陷阱（`Z`、`(null)`、四位年份顺序、费率单位差异）。生成报告前必读，不要凭猜测解读数据。
2. **确认数据缺口**：检查目标船是否缺 GT / 船舶类型 / 识别号。缺 GT 时保赔险、油污险费率算不出来（这两类按总吨位计收保费）。向用户索取或明确标注「待补充」，**不要用行业常识填数**。
3. **跑脚本**：先 `--ship` 单船试跑，检查输出的 `_batch-summary.json` 里 `verify_issues` 是否为空。
4. **抽查内容**：用 python-docx 或提取文本通读一遍，重点核对评级结论、费率数值、赔案金额是否与源表一致。
5. **批量执行**：确认单船无误后再 `--all`。
6. **交付前校验**：脚本内置 `verify()` 已自动跑；若有 `verify_issues` 必须先修再交付。

## 硬约束（来自核保人审阅意见，违反即返工）

这些是用户明确否决过的写法，脚本已内置遵守，手工调整文案时同样适用：

- **禁用倍数换算表述**。不要写「估损金额约为满期保费的 3.88 倍」——用户评价「显得太业余」。直接给估损绝对值（如「估损金额约44万元」），并标注为估算值、以理赔系统立案估损为准。
- **正文不出现保险机构代码**。只写机构全称（如「东海航运保险股份有限公司」），不写 `000202`。机构代码表仅用于内部把代码翻译成名称。
- **报告正文不写评级依据**。第五节只给评级结果，依据通过对话向用户解释即可。依据文本仍保留在 `_batch-summary.json` 中供查阅。
- **不把 IMO 号缺失列为核保建议**。不是每条船都有 IMO 号，其缺失不构成核保关注点。
- **缺失字段显式标注**，写「待补充」，绝不编造。船龄可由识别号推算（见下），不算缺失。
- **无投保记录 ≠ 低风险**。整行 `(null)` 的船评级为中性灰色「无数据」，并在核保建议中提示不能据此认定为优质标的。把它标成绿色「低风险」是危险的空真结论。

## 自动推算的指标

| 指标 | 算法 | 说明 |
|---|---|---|
| 船龄 | 当前年份 − 识别号 `CN` 后四位 | 已用示例船验证：`CN20102397742` → 2010 → 2026−2010 = 16 年 |
| 保赔险/油污险费率 | 单均保费 ÷ 总吨位GT，单位「元/GT」 | 这两类按总吨位计收保费；无 GT 则不算 |
| 船壳险费率 | 单均保费 ÷ 单均保额，单位「‰」 | 船壳险一般仅统计主险保额，费率仅供参考 |
| 未决估损 | 最高（已决+未决 − 已决）百分点 × 单均保费 | 取整到万元，标注为估算值 |

费率口径**已用示例船反推验证**：45318÷1743=26.00 元/gt、7553÷1743=4.33 元/gt、148000÷35000000=4.23‰，与模板记载完全吻合。

## 风险评级规则

评级依据在 `references/字段解读规则.md` 有完整条款。要点：

- **业务品质**：高风险需满足任一（≥3险种且超100%的数值≥4个 / 当年或去年任一数值>500% / 出险数量>3）；低风险需**同时**满足（所有已决+未决均<55 / 出险合计≤1 / 赔案金额合计<10万）；其余中风险。
- **欺诈风险**：三个「近1年起保当月/2个月/3个月出险保单数量及占比」全为 `0,0.00%` → 低风险；当月起险字段非 `0,0.00%` → 高风险；其余中风险。
- **配色**（评级词单独成 run 并加粗）：低风险 `00A651` 绿、中风险 `D6A419`、高风险 `E02020` 红、无数据 `808080` 灰。
  中风险**不用纯黄**——纯黄在白底和黑白打印下几乎不可读，用加深的琥珀黄。

## 排版规范

排版基准存在 `assets/base-template.docx`（由总公司模板清理而来：保留 styles/theme/settings/sectPr，移除批注与示例正文）。可用 `--template` 指定自己的模板覆盖。

- 报告标题：华文中宋 28 半磅（小二号），居中
- 节标题（一、二、…）：黑体 24 半磅（小四号）
- 正文：仿宋 21 半磅（10.5pt，来自模板 docDefaults），险种标签 run 加粗
- 页面：A4，边距上下 1440 / 左右 1800 twips，`docGrid` lines/312
- 六节结构固定：船舶档案｜业务品质分析｜欺诈风险识别｜近3年单均保额保费｜风险提示｜核保建议，末尾附报告生成日期 + AI 免责声明

## 水印

默认 `总公司/1010000789`，可用 `--watermark` 覆盖；不加水印用 `--no-watermark`（**不要**用 `--watermark ""`，PowerShell 会丢弃空字符串参数）。

实现为 VML 艺术字页眉：`rotation:315`（左下→右上斜式）、银灰 `#c0c0c0`、`opacity:.5`、页面居中、`z-index` 负值衬于文字下方，每页均带。宽高按字形比例计算（汉字 1em、ASCII 数字约 0.5em），避免文字被拉伸变形；旋转后外接框超过页宽时**等比缩小字号**（非拉伸）并预留 1% 边距，`verify()` 会检查是否溢出。


## 数据缺口

智盾案例表通常缺以下字段，批量前需向用户索取并写入 `--extras`：

- **总吨位（GT）**——影响保赔险/油污险费率能否计算
- **船舶类型**、**船龄**（有识别号则自动推算，无需索取）
- **船舶识别号**——部分船该列为空；缺失则船龄也推不出来

不要把缺口留给用户去发现：生成前先检查 `_batch-summary.json` 里的 `gt` / `age` 是否为 `null`，主动提示补充。

## 交付前校验清单

脚本 `verify()` 已自动检查：zip 完整性、XML 合法性、水印部件与关系链、`rotation:315`、Content Types 注册、示例船名残留、批注残留、被禁用的倍数表述、「评级依据」段落残留。

人工再抽查：评级结论与源表数据是否吻合、费率数值是否正确、缺失字段是否已标注「待补充」、承保公司是否写全称。
